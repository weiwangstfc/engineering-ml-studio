# Neural-network correctness & validation report

**Scope.** Before finalising Phase 2, the large gap between the **browser** neural-network result
(test R² ≈ 0.99) and the **notebook** result (test R² ≈ 0.79) was audited to rule out data leakage,
evaluation mistakes, or tuning against the test set, and to decide whether the browser neural network
is reliable and educationally honest as implemented.

**Bottom line (verdict): A — suitable as implemented.** The browser neural-network training and
evaluation code required **no changes**. The ~0.99 result is genuine and near the dataset's
irreducible-noise ceiling; the pipeline is free of train/validation/test leakage; the default preset
is stable and deterministic. The gap to the notebook's 0.79 is a **training-length / early-stopping
artifact**, not leakage or an implementation-quality difference — both environments reach ~0.99 when
the network is trained to convergence. The corrections made were to **documentation, the notebook's
framing, and test coverage** (details in §11), not to the model.

---

## 1. Data provenance

- **Dataset:** `examples/pipe_pressure_drop_sample.csv`, 500 rows, generated by
  `scripts/generate_pipe_pressure_drop.py` (seed 42).
- **Physics:** Darcy–Weisbach pressure drop with the Haaland turbulent friction factor; fixed wall
  roughness (ε = 0.045 mm, not a feature). Diameter and viscosity are log-uniform sampled; length,
  velocity, density uniform.
- **Noise:** multiplicative lognormal, `exp(N(0, σ))` with σ = 0.05 (~5 % scatter).
- **Features (5, all numeric):** `pipe_length_m`, `pipe_diameter_m`, `flow_velocity_m_s`,
  `fluid_density_kg_m3`, `dynamic_viscosity_pa_s`. **Target:** `pressure_drop_kpa`.

**Target statistics (kPa):** min ≈ 0.05, max ≈ 193, mean ≈ 24.9, median ≈ 8.4, std ≈ 38.6,
coefficient of variation ≈ 1.55; the target spans ~2400× (≈ 3.4 decades). R² on this target is
therefore **variance-dominated by the large values**, so a good smooth model legitimately reaches
very high R².

## 2. The split (70 / 15 / 15)

`js/explore.js` uses `SPLIT = { seed: 42, percentages: { training: 70, validation: 15, test: 15 } }`
via `MLCore.splitRows` (seeded shuffle → disjoint slices). Empirically (replicating the exact Explore
pipeline in-browser):

| Split | Rows | Unique indices |
| --- | --- | --- |
| Training | 350 | 350 |
| Validation | 75 | 75 |
| Test | 75 | 75 |
| **Union** | **500** | **500 (= all rows)** |

Overlaps train∩val = train∩test = val∩test = **0** on every seed tested. No row appears in more than
one split; every row is used exactly once.

## 3. Data-leakage audit (result: no leakage)

Traced through the real functions in `js/explore.js › runPipeline`, `js/ml-core.js`, and
`js/advanced-core.js`, and confirmed empirically:

- **Input scaling fitted on training only.** `fitPreprocessor` is called with `rawTrain` only.
  Empirical check: for `pipe_length_m` the fitted mean = **15.63809** = the training-set mean, and
  **differs** from the full-dataset mean **15.87908**. Validation and test rows are transformed with
  the train-fitted scaler.
- **Target scaling fitted on training only.** The network standardises the target internally
  (`yMean`, `ySd` computed from the **training** `y`); validation targets are standardised with those
  same training statistics.
- **Validation used only for early stopping.** The 15 % validation set is passed as
  `_validationX/_validationY` and drives early stopping (best-validation-weight restore). The **test**
  set never enters `fit`, early stopping, or model selection.
- **Predictions inverse-transformed before metrics.** Test predictions are mapped back to kPa
  (`mean + sd · network output`) before RMSE/R², so all reported errors are in physical units.
- **Target excluded from inputs.** The feature list never contains the target column; the
  preprocessor's output names exclude it.

These invariants are now pinned by automated tests (§11).

## 4. Is the ~0.99 plausible? (yes — near the noise ceiling)

Reconstructing the **noise-free** Darcy–Weisbach target from the same inputs (diagnostic only — never
fed to any model):

- **Irreducible-noise R² ceiling** (noise-free vs noisy observed) = **0.9962**. This is the best any
  model could achieve; ~0.99 is therefore **not anomalous**.
- Browser NN train↔test gap is small (e.g. seed 42 Small: train RMSE 3.10 kPa, test RMSE 4.78 kPa) —
  no sign of gross overfitting.
- **Worst test residuals** occur at the **high-pressure end** (targets up to ~193 kPa) — expected,
  because multiplicative noise produces larger absolute residuals at large values and the extremes
  are sparsely sampled. Typical worst-case absolute residuals are ~10–25 kPa against targets of
  100–190 kPa (single-digit-percent relative error), consistent with ~5 % noise plus mild model
  error.

test-set leakage. Presets were chosen on training/validation behaviour, stability and training time —
**not** on the best test result.

## 6. Browser ↔ notebook reconciliation

Both use the same problem, the same 70/15/15 proportions, and seed 42, but different split
*implementations* (browser: JS seeded shuffle; notebook: two `train_test_split` calls), so the actual
rows differ. Controlled diagnostic on the **notebook's exact split** (train 350 / val 75 / test 75):

| Model / config | test R² | iters/epochs |
| --- | --- | --- |
| Linear | 0.596 | — |
| Random Forest (sklearn defaults) | 0.846 | — |
| MLP `(32,16)`, notebook config (`early_stopping=True, n_iter_no_change=25`) | **0.788** | **53** |
| MLP `(32,16)`, **early stopping off**, `max_iter=2000` | **0.992** | 491 |
| MLP `(16,)`, early stopping off, `max_iter=2000` | 0.989 | 2000 |

**Conclusion:** the notebook's 0.788 is an **early-stopping underfit** — sklearn's `early_stopping`
watches a small internal validation slice with a relative tolerance and halts after only ~53
iterations. The **same architecture, split and seed** trained to convergence reaches **0.992**,
matching the browser. The browser network's stricter absolute early-stopping criterion and larger
external validation set let it train ~200 epochs, so it converges without underfitting. Neither
implementation was tuned to win, and neither is presented as universally superior.

## 7. Target scaling

The network standardises the target internally and inverse-transforms predictions back to kPa.
This is technically sound here: the target spans ~3.4 decades, so standardising keeps the loss on a
sane scale and initial predictions near the mean, which materially helps gradient-based training. The
round-trip (standardise → train → inverse) is now covered by a unit test asserting predictions are
returned in the target's units (not standardised). Metrics and plots are all in kPa.

## 8. Architecture presets

`ANN_ARCH_PRESETS = { small: (16,), medium: (32,16) }`; **Small is the default**. Selection favours
stability, fast training (~1–2 s), limited overfitting and a clear small-vs-larger contrast. No large
architecture is offered and Explore exposes presets only (no free architecture editing). A unit test
pins the preset→architecture mapping exactly. Based on §5, Small is correctly the default; Medium is
retained as an advanced contrast (its greater variability is itself an honest lesson).

## 9. Loss curve

The collapsed advanced diagnostic plots **training loss** and, when available, **validation loss**
per epoch, drawn only from the model's recorded history (never fabricated). The y-axis is labelled
**"Loss (scaled units)"** — honest, since the target is standardised internally. It stays a
secondary, collapsed card.

## 10. Stage 4 interpretation wording

Deterministic, rule-based text only. It already states that good performance here "does not establish
that neural networks are superior in general", that the result is "one synthetic dataset … [it does]
not prove one model is best in general", and repeats the extrapolation and physical-validation
cautions. It never claims the NN is best or that a high R² proves the physics. No wording change was
required.

## 14. Limitations

- Synthetic, single-dataset demonstration on an **easy** target (noise ceiling ≈ 0.996) — says
  nothing about noisier/smaller/real engineering data.
- The Medium preset is more variable than Small; Small is the default for that reason.
- The browser network is a compact educational implementation, not a production DL framework.
- High test performance does **not** prove the physics or justify real design use; extrapolation
  beyond the demonstrated range remains unreliable.

## 15. Verdict

**A — Suitable as implemented.** The browser neural network is leakage-free, deterministic, stable at
its default preset, and its ~0.99 result is genuine and near the irreducible-noise ceiling. No
model-code changes were required. Corrections were limited to documentation, the notebook's framing,
and added leakage-guard tests. An **optional** future refinement (not required for correctness) would
be to lengthen the Medium preset's early-stopping patience to reduce its occasional underfit.
