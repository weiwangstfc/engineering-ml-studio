Is this tool right for my problem?

A good fit when…

  • you want to predict one number — a pressure drop, a strength, a temperature, an efficiency;
  • your data is a table: one row per test, specimen or simulation run, one column per variable;
  • you have roughly 30 to 50,000 rows (it is most responsive below about 10,000);
  • the inputs you would use are known when you make a prediction.

Look elsewhere when you need to…

  • predict a category, such as pass/fail or failure mode;
  • forecast over time, or learn from images, signals or spectra;
  • predict whole fields (a CFD or FEA solution) or several linked outputs at once.

Understand the problem: pressure drop in a pipe

  • What you are doing: getting to know the engineering problem before modelling it.
  • Why it matters: knowing the inputs, the target and the expected physical trends helps you judge whether a model is sensible.
  • What to look for: the units, the range of the data, and that this is a synthetic demonstration.
Learning path · six examples

Work through the examples in order: each one teaches a new idea, from the basic workflow to a deliberately hard, noisy problem, finishing with real measurements. Pipe pressure drop is the starting point.

Choose an approach

  • What you are doing: deciding how much flexibility the tool should use to learn the relationship.
  • Why it matters: a simple trend is easy to read, while a flexible relationship can fit curved, nonlinear behaviour.
  • What to look for: start simple, then try a more flexible approach and see whether it does better.

The simple trend is a good starting point. Many engineering quantities depend on their inputs in a curved, nonlinear way, so a more flexible relationship often fits better. The trade-off is that a very flexible model can overfit — following the training data too closely and generalising worse to new conditions. A more complex model is not automatically more accurate or more suitable for engineering use. On small tabular datasets like this one, a neural network may not beat a well-tuned tree-based method.

What do these model names mean?
  • Linear Regression learns a weighted relationship: each input is multiplied by a number and the results are added up. Easy to interpret, but it may struggle with nonlinearity.
  • Decision Tree divides the input conditions into regions and predicts a value for each. It captures nonlinear behaviour, but a deep tree may overfit.
  • Random Forest combines many trees for a more stable prediction. It is less transparent than a single relationship and may extrapolate poorly beyond the data.
  • Neural network combines layers of simple units to learn nonlinear relationships. It is flexible and powerful, but needs its inputs put on a common scale, has more settings to choose, trains more slowly, and can overfit small datasets. It is offered here as an advanced option, not the default.
Network size

The inputs are automatically put on a common scale before training (the network needs this), and predictions are converted back to the target’s own units (kPa), so the errors and charts stay in real units. You do not need to configure any of this.

Preparing your own data for Project mode

The Explore datasets are clean. Real measurement and simulation data rarely is, and most problems at upload come from the layout of the file rather than from the data. Before you load a CSV in Project mode, check that:

  • One row is one measurement — one test, specimen, operating point or simulation run.
  • One column is one variable, with a single header row. No merged cells, notes, totals or blank rows inside the table.
  • Units are in the column names, not in the cells: pressure_drop_kpa with values like 12.4, not 12.4 kPa.
  • Numbers use a decimal point (12.4, not 12,4) and no thousands separators.
  • Missing values are left blank — not written as 0, −999 or “n/a”, which the model would take as real values.
  • Every input is known when you predict. Leave out anything measured after the event you want to predict, or the model will appear far better than it is.
  • Keep identifiers (sample or run IDs) for traceability. Project mode recognises them and leaves them out of the inputs.
  • Grouped or ordered data is noted. If rows come from a few rigs, batches or a time series, you will want a grouped or time-based split in stage 4.

Beyond this tool: what it doesn't cover, and what to use instead

This tool predicts one numeric quantity from a table of measurements, with a set of well-understood regression models. That covers many engineering questions, but not all of them. If your problem is one of the types below, no model choice here will help: you need a different kind of method. The Python notebooks above are the natural next step, using the same libraries named here.

About Engineering ML Studio

Engineering ML Studio is a browser-based tool for exploring, understanding and applying machine-learning regression to engineering data. It is aimed at engineers rather than machine-learning specialists.

  • All calculations run locally in your browser; data you load is not sent to any application server.
  • It is intended for learning, exploration and small engineering projects.
  • It is not a validated safety-critical analysis tool. Always independently verify any output before relying on it.

Stage 2 of 6

Choose inputs and quantity to predict

Stage guidance

What you are doing: choose which columns describe the engineering conditions (input variables) and which quantity the model should predict.

Why it matters: the model can only learn from the input variables you provide.

Look for: avoid including identifiers, duplicated quantities, or information that would not be available when making a future prediction.

1 Quantity to predict (target)

The one measured quantity you want the model to predict — for example pressure drop or yield strength. Every other column can be used as an input.

Predictions and uncertainty bounds are converted back to the original target scale.

Why transform the target, and when?

A transformation changes the scale the model learns on; results are always converted back, so you still see predictions in the original units.

  • Consider one when the quantity you predict spans orders of magnitude (for example heat loss from a few watts to tens of kilowatts), is strongly skewed with a long tail of large values, or has errors that grow with its size. Without it, a few very large values dominate training and small values are fitted poorly.
  • Why a logarithm helps: it compresses the range, and it turns a multiplicative relationship such as Q = h · A · ΔT into an additive one, which straight-line models can learn.
  • Which one: Natural logarithm for strictly positive quantities; Square root for counts or mildly skewed non-negative values; Yeo–Johnson if the target can be zero or negative; Box–Cox and Yeo–Johnson estimate the strength of the transformation from the training data.
  • When not to: if the target is roughly symmetric and spans a modest range, None is the right choice — a transformation then adds complexity for no gain.
  • Check rather than guess: train once with and once without, then compare validation RMSE in Evaluate results.

2 Input variables (features)

The measured conditions the model uses to predict the target. Suggested input variables are every column except the target and columns that look like identifiers (row numbers, sample IDs): an identifier lets a model memorise rows instead of learning the engineering relationship. 1 A starting point for your data

    No rule can tell which model will be best for your data — that is decided by comparing them on validation error.

    2 Choose a model: recommended starting models

    Other modelling approachesNine more models, grouped by family: models in the same family work in a similar way.

    Equation-based family

    One explicit equation that is easy to explain and check against the physics. The straight-line variants differ in how they handle correlated inputs, outliers and bounds; the polynomial response surface adds squared and interaction terms to follow smooth curves.

    Tree-based family

    Yes/no splits on the inputs. They capture curved relationships and interactions; Random forest and Gradient-boosted trees above are the stronger members.

    Similarity-based family

    Predict from training rows that resemble the new one, or from a smooth surface through them. Best suited to smaller datasets.

    Neural network

    The most flexible family, and the one that needs the most data and care. Compare it against a tree ensemble before relying on it.

    Stage 5 of 6

    Evaluate results

    Formally: model diagnostics. Read the metrics and diagnostic plots to judge whether the model is good enough and where it can be trusted.

    Stage guidance

    What you are doing: inspect how well the trained model predicts on data it did not learn from.

    Why it matters: headline accuracy can hide problems — bias in part of the range, poor coverage of the prediction intervals, or weak performance for a particular group.

    Look for: points scattered close to the diagonal in Actual vs predicted, residuals with no obvious pattern, and interval coverage close to the level you requested.

    1 How good is the model?

    Judge the model mainly on the Test row of the table: data it never saw while training or choosing settings. A training error much lower than the test error is a sign of overfitting.

    Diagnostic plot settings

    Actual vs predicted

    Good: points close to the dashed diagonal across the whole range.

    Actual and predicted vs input feature

    Good: the predictions follow the measured trend against this input.

    2 Check the errorsWhere and how the model is wrong: residual plots, each with what good looks like.

    A residual is measured minus predicted. Patterns in the residuals show what the model has missed; good residuals look like random scatter around zero.

    Residuals vs predicted

    Good: a shapeless band around zero. A curve means a missed trend; a funnel means errors that grow with the size of the value.

    Residual distribution

    Good: roughly symmetric around zero. A long tail means a few large misses worth investigating.

    Residuals vs input feature

    Good: no pattern. A curve means the model misses how this input acts.

    Residual Q–Q plot

    Good: points close to the line. Mainly matters for interval methods that assume normally distributed errors.

    Residuals by source

    Good: a similar spread for every group. One group far off means the model does not transfer to it.

    3 UncertaintyHow wide the prediction intervals are, and where the model is least certain.
    What does a prediction interval mean?

    A prediction interval gives a range of plausible values for an individual prediction. For example, a 90% prediction interval is designed to contain the actual value for approximately 90% of comparable future observations, under the method's assumptions. A wider interval indicates greater predictive uncertainty.

    Interval width vs prediction

    Shows where the model is least certain. Wider intervals in part of the range point to sparse or noisy data there.

    The Full Studio hybrid edition may request pinned public JavaScript libraries at startup. Strict-offline and prediction-only editions use bundled local libraries only. CSV data are never sent to a CDN.

    Downloaded projects, models and prediction files may contain sensitive derived information. Store and share them appropriately.

    What the data-quality assistant checks

    The assistant runs local checks when the target or selected features change. It flags duplicate rows, missing values, constant or near-constant columns, ID-like features, high-cardinality categories, missing target values, features equal to the target, and extremely high numeric correlation with the target.

    Severity: critical findings can invalidate fitting or interpretation; warnings need review; information items explain workflow state. These checks do not verify units, scientific plausibility, sampling representativeness, causal validity, or every form of target leakage.

    Glossary

    Plain-language definitions of the terms used in this tool. Where the tool uses two words for the same thing, both are given.

    Coverage
    How often the prediction intervals actually contained the true value. It should be close to the level requested.
    Cross-validation
    Re-splitting the training rows several times so that each row takes a turn in validation. It gives a steadier score than a single split, which matters most for small datasets.
    Data leakage
    Information from outside the training rows — for example a quantity measured after the event, or near-duplicate rows on both sides of the split — that makes a model look better than it will really be.
    Decision tree, random forest, gradient boosting
    Models built from yes/no splits on the inputs. A forest averages many trees; gradient boosting builds small trees that each correct the last.
    Extrapolation
    Predicting for inputs outside the range the model was trained on. Results there can be unreliable.
    Feature importance
    How much the fitted model relied on each input. It describes the model, not proof of physical cause and effect.
    Hyperparameter
    A setting chosen before training, such as a tree’s depth or a network’s size, as opposed to what the model learns from the data.
    Identifier column
    A column that labels rows (sample ID, run number) rather than measuring anything. It is kept for traceability but excluded from the inputs, because a model could memorise it instead of learning the physics.
    Input variable
    A measured condition the model uses to make a prediction, such as pipe diameter or temperature. Also called a feature or input.
    Linear regression
    A model that predicts with one weighted sum of the inputs: easy to explain, and the baseline other models should beat.
    MAE
    Mean absolute error: the average size of the errors, ignoring whether predictions were too high or too low. It is never larger than RMSE.
    Neural network
    Layers of weighted sums with non-linear steps between them. Very flexible, but needs more data and care than the other models.
    Noise floor
    The scatter in the measurements themselves. No model can predict it, so it limits how accurate any model can be.
    One-hot encoding
    Turning a text category into 0/1 columns, one per category, so no false order is implied.
    Overfitting
    Fitting quirks and noise in the training rows that do not carry over to new data. The sign is a test error much larger than the training error.
    Prediction interval
    A range around a prediction that is meant to contain the true value a stated share of the time, for example 95%.
    Random seed
    A number that fixes the random shuffle, so the same seed always gives the same split and the same results.
    Regression
    Predicting a number on a continuous scale. This tool does regression only; predicting a category is classification.
    Residual
    Measured value minus predicted value for one row. Good residuals look like random scatter around zero.
    RMSE
    Root-mean-square error: a typical prediction error in the target’s own units, with large errors weighted heavily.
    R²
    The share of the variation in the target that the model explains, compared with always predicting the average. 1 is perfect; 0 is no better than the average.
    Standardisation
    Rescaling each input to an average of 0 and a standard deviation of 1, so inputs in different units are comparable. Learned from the training rows only.
    Target
    The one quantity the model predicts, such as pressure drop or yield strength. Also called the quantity to predict or output.
    Target transformation
    Modelling the target on another scale, such as its logarithm, and converting predictions back. Useful when the target spans orders of magnitude.
    Test set
    Rows kept aside until the end for one independent check. The test score is the honest estimate of how the model will do on new data.
    Training set
    The rows the model learns from.
    Underfitting
    A model too simple to follow the real relationship, so it is inaccurate on both training and test data.
    Validation set
    Rows held back from training and used to choose model settings and to compare models.
